# 02 — Database: schema, migrations, backfills, connections

PostgreSQL is the only source of truth. This document standardizes the shape of tables, how to change the schema safely in
production without staging, and how the application connects to managed Postgres (Supabase) through the pooler.

Markers: **MUST / MUST NOT / SHOULD**. **(improvement)** = a lesson from production incidents that is not common practice yet; required for new projects.

Reference numbers for context: PostgreSQL 17.6 on Supabase Micro compute (`max_connections` 60, ±23
backends when quiet); Supavisor pooler with Pool Size 15, Max Client Connections 200; production migrations take 0.1–0.4 s
per file. The rules below are written for data that keeps growing.

---

## 1. Schema conventions

### 1.1 Identity: `uuid` + `randid`

- Every entity table that is read through a model **MUST** have two identity columns:
  - `uuid` — primary key, used for joins, FKs, and API parameters;
  - `randid` — 16 characters `[a-zA-Z0-9]`, `UNIQUE`, a short random handle (members of certain cache indexes,
    tie-break for old cursors, codes that may appear in public URLs).
- Both are generated by the **application** through `redifu.InitRecord` (`uuid` = UUIDv4, `randid` from `crypto/rand`,
  `created_at = updated_at = now UTC`). `InitRecord` **MUST NOT** be called for a row loaded from the DB (a new randid
  orphans the index).
- **MUST (improvement)** use one ID type across the whole schema: Postgres `uuid` columns. Mixing `varchar(255)`
  and `uuid` means a `uuid` FK to a `varchar` table cannot be created, and queries need `::text`, which disables the index
  (including in `FOR UPDATE`). The `randid` width is standardized too (`varchar(16)`).
- **(improvement)** a SQL function `gen_randid()` with the same alphabet as Go, created by the first migration, for
  backfills.
- Other valid shapes:
  - pure join tables: no `uuid`/`randid`, composite PK, always rewritten in full;
  - projection/derived tables: PK = the business key (`booking_stat_facts(booking_uuid)`, `marketplace_listings(user_uuid)`);
  - queues/outboxes: `id BIGSERIAL` as the order (exception: the notification outbox uses `uuid` + `dedupe_key`).
- **Human-readable codes** (6-character booking ID, ticket code, receipt number `KSR-YYMMDD-NNN`): **MUST** be `UNIQUE`,
  with collisions retried **inside a `SAVEPOINT`** (§3.6) — or taken from a counter (§1.15). A retry without a savepoint
  attempts the INSERT again in a transaction that is already aborted (a classic bug).

### 1.2 `created_at` / `updated_at`

- **MUST**: `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` and `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`.
  Incident: `updated_at` nullable without a default + a model with a non-pointer `time.Time` → the insert wrote only
  `created_at`, and the first read failed with `storing driver.Value type <nil> into type *time.Time`.
- **No `updated_at` trigger:** every repository UPDATE writes `updated_at` itself — one place, visible in the SQL.
- `now()` = the time at the **start of the transaction**. When the `created_at` order matters and the row is written after
  waiting for a lock, set the time in the application after the lock, or default to `clock_timestamp()` (like
  `redifu_outbox.created_at`).
- **A status that has a time** = one nullable timestamp (`email_verified_at`, `deactivated_at`, `used_at`, `revoked_at`,
  `read_at`), not a boolean + timestamp pair that can disagree.
- **MUST NOT** store "zero time" (`0001-01-01`) for "not yet" — use NULL. **MUST NOT** mix time units in audit columns
  (unix millis vs timestamp).

### 1.3 Owner column (multi-tenant)

- Every row owned by an account **MUST** carry an owner column (`user_uuid` = the account's `users.uuid`; a business
  account may use `team_uuid`). Indexes put the owner first: `(user_uuid, …)`.
- Every write to an owner's row **MUST** carry the owner in the `WHERE`; 0 rows affected = NotFound (§3.3).
- Ownership **SHOULD** also be enforced by the DB with a **composite FK** `(child_ref, user_uuid) → parent(uuid, user_uuid)`
  (target `UNIQUE (uuid, user_uuid)` on the parent): a child cannot point to a parent owned by another account.
- Repeat the owner column in child tables when uniqueness must be per owner (`UNIQUE (user_uuid, phone_number)`).
- Side tables `user_*` (reset tokens, email verification, device tokens, preferences) may go without an FK; account
  deletion deletes them explicitly (§1.4).

### 1.4 Soft delete, hard delete, retention, account deletion

- **Soft delete** (`deleted_at TIMESTAMPTZ NULL`) for user-owned catalog entities that history refers to, or whose names
  must be reusable. Their unique constraints **MUST** be partial `WHERE deleted_at IS NULL`; list indexes are partial too.
- **Hard delete** for the rest: entities without history, device tokens at logout, outbox rows already processed,
  age-based purges.
- **Batched purge:** `DELETE FROM t WHERE uuid IN (SELECT uuid FROM t WHERE <status> AND updated_at < $before LIMIT $n)`
  with an index on `(status, updated_at)`.
- **Account deletion** (proven pattern, 90 days):
  - state on the account row: `account_status` (`ACTIVE` | `PENDING_DELETION`) + `deletion_requested_at` +
    `deletion_scheduled_at`, with a cross-column CHECK so the three move together;
  - an audit record (`user_account_deletions`) without FK and without PII, which survives after the account is gone;
  - a worker purges after the due date (or immediately for an admin force-delete): lock with `FOR UPDATE SKIP LOCKED` →
    delete storage files first → delete all rows in one transaction through an **explicit DELETE list**, children before
    parents;
  - data retained for legal/financial reasons (ledger, billing, KYC, audit) is listed explicitly;
  - state columns like these **MUST** be written only by their dedicated statements (a generic Update that writes back
    the whole row can restore `ACTIVE`).
- **(improvement)** every new table with an owner column must be in the account purge list **or** the retained-data list,
  enforced by a test.
- **SHOULD** drop PII columns that are never read (example: IP/user agent columns that only contain the load balancer's
  IP).
- **Append-only audit**: no UPDATE/DELETE in code and no FK (`user_role_changes`, `user_account_deletions`,
  `ledger_entries`).

### 1.5 Enum / status

- **MUST**: status = `VARCHAR(n)` holding SCREAMING_SNAKE Go constants. **MUST NOT** use a Postgres `ENUM` (adding a
  value requires DDL).
- **MUST**: `CHECK (col IN (…))` for **closed** sets that the code `switch`es on — the column stays honest even when
  written by a backfill/psql. **MUST NOT** add a CHECK for **open** sets (a gateway-owned channel list, the notification
  catalog in code, data sources that can grow).
- **Cross-column CHECK** for state machines: `(status IN ('DONE','REJECTED')) = (closed_at IS NOT NULL)`.
- Derived statuses **SHOULD** not be stored (EXPIRED is computed from `expires_at` when read).
- A tri-state boolean (NULL = "follow the rule") is allowed, with the meaning of NULL documented.

### 1.6 Money and numbers

- **MUST**: money = `BIGINT` in the **whole currency unit** the project agrees on (e.g. whole rupiah) and `int64`
  in Go. **MUST NOT** use float or `numeric` for amounts. Values that cannot be represented are **rejected**, not
  rounded.
- Any unit other than the default **MUST** be named in the field/column name (`_sen`, `…Minor`). Incident: a settlement
  fee with two decimals; one code path filled in sen, another rupiah, and the field name had no unit → a false mismatch
  blocked settlement.
- Rates: basis points as `INTEGER` (`rate_bp BETWEEN 1 AND 10000`); fee percentages `NUMERIC(10,6)`; **MUST NOT** use
  float.
- CHECK amount ranges (`price >= 0`, `amount > 0`, a reasonable upper bound).
- **Numbers from a gateway that arrive as JSON floats** are read as the nearest smallest unit when the difference is
  clearly float noise (`6908.139999999999`), and **rejected** when there really is a third decimal. (Incident: the
  settlement webhook was answered with 400.)
- The meaning of an amount **MUST** be explained with `COMMENT ON COLUMN` (e.g. "transfer fee is taken out of amount");
  the per-row amount = "what is charged", the pre-discount value goes in a separate nullable column.
- **Insert-only ledger**: corrections through compensating entries; status transitions that move money use CAS (§1.17).
- Coordinates: `double precision` (or PostGIS), not `varchar`.

### 1.7 Time and time zones

- Processes **MUST** run in UTC: `time.Local = time.UTC` at start.
- **Instants:** **MUST** be `TIMESTAMPTZ` in new tables (never `timestamp without time zone` columns holding UTC wall-clock
  time).
- **Schedule instants** may be `BIGINT` unix seconds (e.g. booking `start_time`/`end_time`) as long as this is
  consistent; overlap is checked as a half-open `int8range(start, end)`.
- **Durations** in minutes as `INTEGER`, with a grid CHECK when the scheduling engine works on a grid (`% 5 = 0`).
- **Civil dates** (`DATE`) are interpreted in the account's zone **when used**, not frozen at creation.
- **Zones:** canonical IANA names (`users.timezone_location`, validated; names that `AT TIME ZONE` also accepts); offsets
  and abbreviations are **derived by the server**; `timezone_auto BOOLEAN NOT NULL DEFAULT TRUE` when the zone follows
  the device. Bookings store instants; a zone change does not shift bookings.
- **Projections per local date** store the zone they used (`timezone`, `local_date`, `local_hour`) and are re-projected
  when the owner's zone changes.
- Platform schedules that stay fixed to the business time zone (e.g. settlement at 13:00 WIB) are recorded explicitly as
  exceptions.

### 1.8 JSONB, arrays, full-text

- **SHOULD**: JSONB for client-owned settings objects that the server does not interpret (document design, theme) and
  for snapshots (notification payloads, voucher terms, purge summaries).
- **MUST**: `CHECK (col IS NULL OR jsonb_typeof(col) = 'object')` (or `'array'`): a wrong scalar/array in a column that
  is read on every login fails **the whole row**.
- The content's shape is validated by the application (with a size limit); default `NOT NULL DEFAULT '{}'::jsonb`, or
  nullable when NULL means "never set".
- **MUST NOT** use `bytea` while `POSTGRES_BINARY_PARAMETERS` is on (the driver wrapper sends `[]byte` as text, §6.5);
  store bytes as base64 in JSONB/text.
- Arrays: `TEXT[] NOT NULL DEFAULT '{}'` + GIN + a membership CHECK `modes <@ ARRAY[...]::TEXT[]`.
- Search in Postgres: `TSVECTOR` + GIN, case/accent folding in Go; sort columns `COLLATE "C"`. The main search uses
  Typesense ([05-workers-and-integrations.md](05-workers-and-integrations.md)).

### 1.9 Copy columns (snapshots)

- Historical records **MUST** copy what they need at creation (service name/price/color, discounts, taxes, fee quotes,
  staff/resource names), without an FK to the source, never recomputed. Tomorrow's price change does not touch today's
  transactions.
- Copies **MUST** be written **only by Insert**; a generic Update never touches them.
- Denormalized copies that must follow their parent (e.g. the per-booking staff/resource table follows the booking's time
  & status) are maintained by **one trigger** `AFTER UPDATE OF <column> … WHEN (OLD.x IS DISTINCT FROM NEW.x …)`.

### 1.10 Constraints

- **DB constraints are the authoritative guard.** A pre-check in the usecase only provides a friendly 409 answer (a
  pre-check can read stale data).
- Partial UNIQUE (`WHERE status = 'ACTIVE'`, `WHERE deleted_at IS NULL`); case-insensitive uniqueness
  `UNIQUE INDEX … (user_uuid, lower(name))`.
- Nullable dimensions in a unique key: an expression index `(…, COALESCE(col, ''))` (queries **must** use the same
  expression), a sentinel `NOT NULL DEFAULT ''`, or `UNIQUE NULLS NOT DISTINCT` (PG ≥ 15).
- **EXCLUDE** for "must not overlap" (`CREATE EXTENSION IF NOT EXISTS btree_gist`): half-open
  `int8range(start_time, end_time)` per owner/member/resource; `daterange(…, '[]')` for inclusive date ranges; a `23P01`
  violation → 409.
- **FK `ON DELETE`:** `CASCADE` for owned children; `SET NULL` for optional pointers (`ON DELETE SET NULL (col)` with a
  column list on PG ≥ 15 so the owner in a composite FK is not NULLed as well); **no FK** for audit, copies, inboxes, side
  `user_*` tables.
- CHECK cross-column invariants (`end_time > start_time`, slug format `^[a-z0-9]+(-[a-z0-9]+)*$`).
- String defaults **MUST** always be quoted: an unquoted `DEFAULT USER` = `CURRENT_USER` (a real incident).

### 1.11 Index design

- Indexes **MUST** follow the bound that actually cuts the scan. Example: for the schedule overlap query
  `start_time < X AND end_time > Y` the index that cuts is `(user_uuid, end_time)`, not `(user_uuid, start_time)`.
- **MUST NOT** apply `::text` or functions to indexed columns in `WHERE`.
- **SHOULD**: partial indexes for queues (`WHERE status = 'PENDING'`), sparsely filled columns, soft-delete lists.
- Every query that runs in a webhook or worker **MUST** have an index **and** a `LIMIT` (example: an invoice number lookup
  without an index = a seq scan on every incoming-money webhook).
- **SHOULD** not add indexes that nobody reads (every write pays for them).
- **EXPLAIN evidence** in the PR: `EXPLAIN (ANALYZE, BUFFERS)` with the exact SQL from the code (via `PREPARE` +
  `SET plan_cache_mode = force_custom_plan`), on a production dump copy **and** on large synthetic data.

### 1.12 Naming (pick one pattern, write it in the project's AGENTS.md)

`idx_<table>_<column…>`, `uq_<table>_<…>`, `<table>_<…>_check`, `<table>_<…>_fkey`, `<table>_<…>_excl`. Constraint names
**MUST** be stable and meaningful: code recognizes violations by constraint name, and idempotent migrations check the name
in `pg_constraint`. A column that is no longer read gets a `DEPRECATED` comment + the number of the migration that will
drop it.

### 1.13 Triggers and `COMMENT ON`

- Triggers **SHOULD** be used only for: (1) denormalized copies that must always match (§1.9); (2) change capture into an
  outbox (`redifu_capture`, [04-caching.md](04-caching.md)). Business logic stays in Go.
- **MUST**: trigger functions use `CREATE OR REPLACE`; triggers use `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER`; a
  migration that changes a trigger rewrites its function in full.
- Column semantics **SHOULD** be recorded in `COMMENT ON` (money columns, deprecated, derived).

### 1.14 Queue, outbox, and job tables

Queues and locks live in Postgres. Outbox rows are **written in the same transaction** as their business change: no event
for a rolled-back transaction, no commit without its event.

| Pattern | Shape | Use |
|---|---|---|
| **Change marker** (search index, statistics projection, marketplace listing) | `id BIGSERIAL`, `<entity>_uuid`, `status` PENDING/FAILED, `attempts`, `last_error`, `created_at`; partial index `(id) WHERE status='PENDING'` | the row only says "this entity changed"; the worker reads the current state (duplicates/late arrivals/random order are harmless); processed = deleted; keeps failing = FAILED |
| **Notification outbox** | outbox (`uuid`, `dedupe_key UNIQUE`, `payload` snapshot, `status` PENDING→PROCESSING→DISPATCHED/SKIPPED/FAILED/CANCELLED, `available_at`, `attempts`, `next_retry_at`, `locked_at`, `group_key`) + a delivery per (notification × channel × recipient) with `idempotency_key UNIQUE` | three layers of idempotency; `SKIP LOCKED` claim; reaper ([05](05-workers-and-integrations.md)) |
| **Cache** | `redifu_outbox` | filled by triggers, drained per owner ([04](04-caching.md)) |
| **Per-entity job** (image render) | one row per entity (`UNIQUE` = the `ON CONFLICT` target), `status`, `retry_count`, `next_retry_at`, `last_error`, `storage_key` | a change that affects the render UPSERTs the job back to PENDING in the same transaction; exponential backoff, then FAILED |

- Worker claims **MUST** take the form `UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED LIMIT n) RETURNING …`:
  claim first, work afterwards; check rows affected; the reaper only returns rows whose `locked_at` is older than a limit
  **longer** than the longest job. (A worker that only SELECTs without claiming is safe only as long as there is one
  instance.)
- **MUST**: a worker never marks a type it does not recognize as done (incident: an old indexer discarded backfill rows
  of a new type).
- Every outbox **MUST** have a purge/retention.

### 1.15 Idempotency and counters

- **External events** (webhooks): an event table with `UNIQUE (provider_event_id)`; duplicates are answered with success.
- **Internal enqueue:** `ON CONFLICT (dedupe_key) DO NOTHING` (revive only for specific states, e.g.
  `WHERE status = 'CANCELLED'`).
- **Per-day counter** (queue/receipt numbers); deleted numbers are not reused:
  ```sql
  INSERT INTO queue_counters (queue_uuid, day, last) VALUES ($1, $2, 1)
  ON CONFLICT (queue_uuid, day) DO UPDATE SET last = queue_counters.last + 1
  RETURNING last;
  ```
- **Absolute aggregates from a buffer:** `GREATEST(old, new)` (repeated copies change nothing).
- **Idempotency keys sent to third parties are derived, not random** (merchant reference from the invoice number), so a
  retry after a timeout carries the same reference.
- **Check-then-create:** `UNIQUE` + `INSERT … ON CONFLICT` + a per-entity lock; "already exists" is read as success,
  followed by a re-read (incident: two concurrent first bookings created duplicate ledger accounts).

### 1.16 Advisory locks

- **MUST**: only the transaction variants (`pg_advisory_xact_lock`, `pg_try_advisory_xact_lock`): a session-level lock
  stays held by the transaction-mode pooler's server connection after its client is gone.
- **Blocking application write locks:** two `int`s with a **class** per feature (class list in `app/constants`):
  ```sql
  SELECT pg_advisory_xact_lock($1::int /* class, e.g. 4271 = owner schedule */, hashtext($2)::int /* owner uuid */);
  ```
- **Non-blocking worker/cache locks:** one 64-bit key with a string prefix unique per consumer (`redifu:`, `bp:`,
  `ledger_accounts:`):
  ```sql
  SELECT pg_try_advisory_xact_lock(hashtextextended('bp:' || $1 || '|' || $2, 0)); -- false = skip, try again later
  ```
- Lock per owner (not per time range). **SHOULD**: an advisory lock instead of `FOR UPDATE` when the row is also locked by
  another path that must not queue behind it (e.g. a separate billing lock so payment webhooks do not queue behind the
  schedule lock).
- **Per-account maximums** (≤ N items) are counted under a per-account advisory lock.

### 1.17 Row locks, CAS, lock order

- **Meaningful status transitions** = a CAS as the **first** statement of their transaction:
  `UPDATE … SET status = $new WHERE uuid = $1 AND status = $old [AND condition]`, check rows affected; `false` → rollback.
  **MUST NOT** stamp the entity in memory and then save it.
- A worker's `DELETE` is also conditioned on status and runs on the primary (potential incident: cleanup deleting a
  just-paid booking because the candidates were read from a replica).
- `SELECT … FOR UPDATE` for rows that are read and then changed; ownership is checked after the lock (`ownedXForUpdate`).
- **MUST**: a deterministic lock order for hot rows (sort before locking; Go map iteration is random → deadlock).

## 2. Building a new schema (new projects)

- **(improvement)** a hand-written `migrations/000_baseline.sql` as the single path that builds the schema, plus a table
  `schema_migrations(version text PRIMARY KEY, sha256 text NOT NULL, applied_at timestamptz NOT NULL DEFAULT now(),
  applied_by text NOT NULL)` that every migration file fills in inside its transaction (`CONCURRENTLY` files write it after
  the validity check). Without a history table the last migration has to be guessed from the schema.
- **(improvement)** CI runs all migrations on an empty Postgres **twice** (proving idempotency), and periodically compares
  the replay's `pg_dump --schema-only` with production — a diff = drift that a migration must close.
- Local & CI Postgres version = production version.

## 3. SQL repository patterns

### 3.1 Read/write pools and when to read the primary

- A repository holds `dbRead` and `dbWrite`; reads go through `dbRead`; writes receive a `*sqlx.Tx` from the usecase; the
  only transaction opener is `IGeneralRepository.BeginTransaction()`.
- Read and write may point to the same endpoint (no replica yet). The code is still written as if there were a
  replica:
  - **MUST**: a pre-check that reads `dbRead` serves only a fast answer; the authoritative check is repeated **inside the
    write transaction, on the primary, under a lock**; the last layer is the constraint.
  - **MUST**: read from the primary when the reader has to see a commit that just happened: worker outboxes/queues, data
    written by another process a second earlier (a newly registered device token), cache seeding.
  - **(improvement)** before reads are actually split off to a replica, mark every read that must go to the primary
    (latent bugs: a 401 loop after a password change, a 404 right after a create).
- **SHOULD**: the `q sqlx.Queryer` pattern (nil = replica, transaction = transaction) so one method serves both.
- Heavy public reads: a read-only transaction with its own limit:
  `BEGIN; SET TRANSACTION READ ONLY; SET LOCAL statement_timeout = '3s'; … COMMIT;`

### 3.2 INSERT/UPDATE

- INSERT/UPDATE are assembled dynamically: only `null.*` fields that are `Valid` are written, with sequential `$n`
  placeholders.
- **MUST**: every SELECT/INSERT **names its columns**; **MUST NOT** use `SELECT *`. Additive columns do not break the old
  binary (the migration may run before the deploy); a new binary that names a new column answers 500 until its migration
  has run → a strict order: **migrate first, then deploy**.
- **MUST NOT** use a generic Update that "writes back the whole model that was just read" for columns that have a dedicated
  writer — the old snapshot overwrites the newer change (CANCELLED back to COMPLETED, PAID down to PARTIALLY_PAID). Columns
  such as account status, role, integration reconnect flags, and copies get their own conditional statement. **SHOULD**
  write only the columns that changed, or use a version column.
- Repository tests against a real Postgres (e2e) complement the sqlmock regexes (sqlmock does not parse SQL).

### 3.3 Owner-scoped writes

```go
query := "UPDATE bookings SET … WHERE uuid = $n AND user_uuid = $m"
result, err := tx.Exec(query, args...)
if errorLog := ownerScopedWriteResult(result, err, constants.ERROR_BOOKING_NOT_FOUND, diag); errorLog != nil {
    return errorLog // affected == 0 → KindNotFound
}
```

### 3.4 Mapping driver errors to Kind

| Source | Kind (HTTP) | Note |
|---|---|---|
| `sql.ErrNoRows` | NotFound (404) | per repository |
| `23505` unique, recognized **by constraint name** | Conflict (409) + domain sentinel | per call site |
| `23P01` exclusion | Conflict (409) | e.g. `ERROR_BOOKING_OVERLAPPING` |
| `55P03` lock_timeout, `57014` statement_timeout/cancel, `25P03` idle-in-transaction | Unavailable (**503**, the client may retry) | centralized in `NewErrorLog` (`IsDatabaseTimeout`) |
| others | Internal (500, masked) | default |

- **MUST**: driver text never reaches the client (it names tables & constraints).
- **(improvement)** a central mapper `23505`/`23P01` → Conflict, with the domain message chosen by constraint name (otherwise
  a `23505` that is not handled explicitly becomes a 500).
- After an error the transaction is aborted; the only way to continue in the same transaction is a `SAVEPOINT`.

### 3.5 Pagination

- Growing lists **MUST** use a **keyset cursor**:
  ```sql
  WHERE user_uuid = $1 AND (created_at, randid COLLATE "C") < ($2, $3)
  ORDER BY created_at DESC, randid COLLATE "C" DESC
  LIMIT $4
  ```
  The cursor is opaque to the client (base64); a broken cursor → 400; a cursor response carries no `total`.
- **MUST**: tie-break on a unique column with `COLLATE "C"` (the default collation compares linguistically; Go and Redis
  compare per byte — without `"C"` the SQL page and the cache page differ).
- **MUST NOT** use `OFFSET` + `COUNT(*)` for new lists (the cost grows with history). Small lists that are read in full may
  use offset page/limit. API contract: [03-api-design.md](03-api-design.md).

### 3.6 Transactions

- Every transaction **MUST** be bounded right after `BEGIN`, in one round trip (`set_config(…, true)` = `SET LOCAL`, works
  in any pooler mode):
  ```sql
  SELECT set_config('lock_timeout','5000ms',true),
         set_config('statement_timeout','30000ms',true),
         set_config('idle_in_transaction_session_timeout','60000ms',true);
  ```
  Values come from env (`POSTGRES_TX_LOCK_TIMEOUT` 5s / `_STATEMENT_TIMEOUT` 30s / `_IDLE_TIMEOUT` 60s). Limit reached →
  503.
- **MUST NOT** call a payment gateway or a third-party API inside a transaction that holds a lock. Incident: checkout called
  the gateway inside a transaction holding the owner lock, and the payment library asked for a second connection from the
  same pool → the task hung completely. Fix: commit first → the outbound call outside the transaction (with a deadline) →
  attach the result in a second transaction under a dedicated lock → the library gets its own pool.
- Retries inside a transaction **MUST** use a `SAVEPOINT`:
  ```sql
  SAVEPOINT ticket_code; INSERT …;  -- fails with 23505 → ROLLBACK TO SAVEPOINT ticket_code; try another code
  ```
- Long commands/backfills: `POSTGRES_TX_STATEMENT_TIMEOUT=0`. A worker that legitimately waits longer for a lock:
  `POSTGRES_TX_LOCK_TIMEOUT=30s` in its task.

## 4. Migrations

### 4.1 Format and numbering

- Plain SQL `migrations/NNN_<what_snake>.sql` (three digits, forward only), run with `psql` by a human (with approval).
- **Gaps in numbering are allowed** (parallel sessions get reserved ranges). **MUST NOT** use duplicate numbers.
- A long-lived branch may renumber its migrations when it lands on master — **only** for migrations that have never run
  anywhere.
- **MUST be forward-only:** an applied migration is never edited; its fix is a new migration (editing means new and old
  DBs are built from different text).
- A library's schema (e.g. the ledger) is migrated by that library's own repo; the application may install triggers on
  library tables with coordination.

### 4.2 Header (required in every file)

```sql
-- Migration: NNN_<what>.sql
-- <Source feature / plan / brief> (docs/plans/…, docs/requirements/…)
--
--   <table/column>   <meaning, unit, meaning of NULL, who writes it>
--
-- Why: <problem solved; incident if any>
-- Deploy order: <BEFORE the code | RIGHT AFTER the deploy | any time> — <reason>
-- Locks/rewrite: <metadata-only? ACCESS EXCLUSIVE for how long? CONCURRENTLY?>
-- Before applying: <pre-check query: duplicates/overlaps that would make the constraint fail>
-- How to run: psql "<dsn :5432>" -X -v ON_ERROR_STOP=1 -f migrations/NNN_<what>.sql
-- Rollback: <how to go back; binary rollback limit: "do not roll back past <sha> without …">
-- Backfill: <backfills/<x>.sql or command; before/after deploy>
-- Additive only | DESTRUCTIVE (approved by <who> on <date>). Idempotent: every statement can run twice.
```

Full template: [`templates/backend/sql/migration.sql`](../templates/backend/sql/migration.sql).

### 4.3 Idempotency

- `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `CREATE [UNIQUE] INDEX [CONCURRENTLY] IF NOT EXISTS`,
  `DROP … IF EXISTS`, `CREATE EXTENSION IF NOT EXISTS`.
- Constraints (Postgres has no `ADD CONSTRAINT IF NOT EXISTS`):
  ```sql
  DO $$ BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_constraint
                   WHERE conrelid = 'users'::regclass AND conname = 'users_theme_preference_check') THEN
      ALTER TABLE users ADD CONSTRAINT users_theme_preference_check CHECK (theme_preference IN ('LIGHT','DARK','SYSTEM'));
    END IF;
  END $$;
  ```
  (or `EXCEPTION WHEN duplicate_object THEN NULL`, or `DROP CONSTRAINT IF EXISTS` + `ADD` when the definition changes
  too).
- Data: `ON CONFLICT … DO NOTHING`; `UPDATE … WHERE <column> IS NULL`; `INSERT … SELECT … WHERE NOT EXISTS (…)`.
- Functions/triggers: `CREATE OR REPLACE FUNCTION`, `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER`.
- **MUST NOT** rely on `CREATE TABLE IF NOT EXISTS` to fix an existing table with a different shape (it is skipped
  silently — a source of drift). **SHOULD** avoid `RENAME COLUMN` (not idempotent, breaks the running binary).

### 4.4 Transactions and locks during migrations

- **MUST**: `-v ON_ERROR_STOP=1` (without it psql carries on after an error and exits with code 0).
- A file that needs atomicity **MUST** write `BEGIN; … COMMIT;` **itself**; the runner (local or production) **never**
  wraps it (`-1`/`--single-transaction`). `CONCURRENTLY` files have no transaction. Local and production are identical.
- **MUST**: `SET LOCAL lock_timeout = '5s'` right after `BEGIN` for an ALTER on a busy table (an ALTER waiting for ACCESS
  EXCLUSIVE behind a long transaction blocks every query behind it; fail fast, retry when it is quiet).
- **Swap constraints in one transaction:** the new constraint is added **before** the old one is dropped.
- **Postcondition guard before COMMIT:** a `DO` block that does `RAISE EXCEPTION` when the result is not as expected → the
  whole transaction rolls back (a drifted production table is never left half-updated).
- PG ≥ 17: `SET LOCAL transaction_timeout` as a safety belt for large data migrations.

### 4.5 Operations: safe, needs special handling, destructive

| Operation | Lock / cost | Rule |
|---|---|---|
| `CREATE TABLE`, a new column with no old readers | brief | safe, additive |
| `ADD COLUMN` nullable without a default | brief ACCESS EXCLUSIVE, metadata-only | safe + `lock_timeout` |
| `ADD COLUMN … NOT NULL DEFAULT <constant>` | metadata-only (PG ≥ 11) | safe; a **volatile** default (`gen_random_uuid()`, `clock_timestamp()`) rewrites the table → fill in stages |
| `DROP NOT NULL`, drop/widen a CHECK | brief | safe, fits the expand phase |
| `SET NOT NULL` | full scan under ACCESS EXCLUSIVE | small table: directly; large: `CHECK (col IS NOT NULL) NOT VALID` → `VALIDATE` → `SET NOT NULL` |
| `ADD CONSTRAINT` CHECK/FK | validates the whole table | `NOT VALID`, then `VALIDATE CONSTRAINT` (does not block writes) |
| `CREATE INDEX` / unique | SHARE: **blocks writes** | live table: `CONCURRENTLY` (§4.6); unique: pre-check for duplicates |
| `EXCLUDE` constraint | ACCESS EXCLUSIVE + GiST build | maintenance window; pre-check for overlaps |
| `ALTER COLUMN TYPE` | rewrite + ACCESS EXCLUSIVE | small tables only; large: new column + staged fill + swap |
| `RENAME COLUMN/TABLE` | metadata-only, **breaks the running binary** | expand/contract: new column → dual write → move reads → drop |
| `DROP COLUMN/TABLE`, `DELETE`, `TRUNCATE`, overwriting UPDATE, narrowing a type | **destructive, irreversible** | explicit user approval; only after the code has stopped reading & writing; record the binary rollback limit |
| `UPDATE` of all rows | row locks + bloat | small: in the migration; large: batched backfill |
| new trigger | brief | consumers must tolerate both before and after |

Production approval classes: [10-workflow.md](10-workflow.md) §6.3.

### 4.6 `CREATE INDEX CONCURRENTLY`

```sql
-- Run: psql "<dsn session :5432>" -X -v ON_ERROR_STOP=1 -f migrations/NNN_x.sql
--      plain psql: no BEGIN/COMMIT, no -1, never through the transaction pooler (:6543)
SET lock_timeout = 0;        -- a timeout that cuts the build leaves an INVALID index
SET statement_timeout = 0;
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_bookings_user_end_time ON bookings (user_uuid, end_time);
-- IF NOT EXISTS also skips an INVALID index left by a failed run: never report success in that state
DO $$ BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_index WHERE indexrelid = to_regclass('idx_bookings_user_end_time') AND indisvalid) THEN
    RAISE EXCEPTION 'idx_bookings_user_end_time is missing or INVALID: DROP INDEX CONCURRENTLY it, then run again';
  END IF;
END $$;
```

- One index per statement; the file contains no other statement that needs a transaction.
- SHARE UPDATE EXCLUSIVE: reads & writes keep running; the build waits for transactions that are already open. **MUST**
  check for transactions open > 1 minute before running (§4.11).
- Failed/cancelled → an INVALID index (ignored by the planner, still maintained on every write):
  `DROP INDEX CONCURRENTLY <name>;`, then run again. Verify `indisvalid = t, indisready = t`.

### 4.7 Constraints on existing data

- The header **MUST** include a pre-check query that finds violating rows before the constraint is added.
- **MUST NOT** resolve violations with a script when a promise to a customer lies behind them (two overlapping bookings
  are two promises) — resolve them together with the owner.
- `NOT VALID` + conditional validation: the rule applies to new writes; old rows are validated only when clean, otherwise
  `RAISE NOTICE` with the count and a runbook reference.

### 4.8 Release order: expand → deploy → contract

Every migration **MUST** answer the code × schema matrix (during a rolling deploy both code versions run at the same
time):

```
|          | old schema | new schema                         |
| old code | ✅         | must be ✅ (additive / relaxed)    |
| new code | must be ✅ or migrate first | ✅                |
```

1. **Expand** (before the deploy): new tables/columns nullable or with a default, constraints relaxed, new keys added.
2. **Fill** (backfill). For rows created by the old code in between: run it before the deploy **and again** after.
3. **Deploy** API + worker (large features: with the switch off at first).
4. **Turn the switch on**, then run the backfills/commands that need the new code.
5. **Contract** (after the release is live on **every** task): drop old keys/columns/tables; destructive steps need
   approval; the header records the rollback limit ("do not roll the BE back past <sha> after this migration").

- **Replacing a unique key used by `ON CONFLICT`:** the old binary needs an exactly matching unique index → the new key is
  added (expand), the old key is dropped **right after** the deploy.
- **Incompatible migration that cannot be split:** snapshot → stop the old backend → a one-transaction migration (safe to
  rerun) → start the new backend; the matrix shows a window without data damage.
- **Consumer triggers** (cache) are applied according to which side tolerates the other side's absence — write it in the
  header.
- **Data only** (reference data) is safe with any binary.

### 4.9 Data in migrations vs backfills

- **In the migration:** data that is part of the schema change (a default plus backfilling a toggle, grandfathering
  `email_verified_at = created_at` — not `NOW()`, reference data, new access keys).
- **In a backfill:** whatever is too big, too slow, or too optional to block the deploy (enqueue all rows to a worker,
  re-index).
- SQL logic that mirrors Go: `pg_temp` functions "statement for statement" or `TEMP … ON COMMIT DROP`, proven identical
  to Go on synthetic data; **only through the session pooler** (temporary tables are not safe in transaction mode).
- A data migration produced by a tool is copied exactly from the tool's export + a guard before COMMIT; back up each table
  before rewriting reference data.
- A unit test reads the migration SQL to make sure literals that also exist in the Go code are identical.

### 4.10 Running migrations in production

1. User **approval** in that session (or a general batch approval for the non-destructive class). Reading production may
   also need approval; without read approval, analysis uses a table restore from a local dump (§7.2).
2. **Deploy lock**; every step is logged (UTC, SHA, duration) ([10-workflow.md](10-workflow.md) §6.5).
3. **Read-only probe:** which migrations already exist (§4.11), affected rows, long transactions.
4. **Backup:** `pg_dump -Fc` to `~/backup/<db>_<YYYYMMDD_HHMM>_pre<NNN>.dump` (mode 600; `pg_dump` with the same major
   version as the server); tables that get rewritten are dumped separately; the psql log is kept.
5. **Test first** on a production dump copy with all migrations since that dump, **twice** (idempotent); dry run
   `BEGIN; …; ROLLBACK;` or count the affected rows.
6. **Run** through the **session pooler `:5432`** (never `:6543`), **one** short psql connection that is closed right
   away, `-X -v ON_ERROR_STOP=1`, `lock_timeout 5s`, transaction mode as the header says.
7. **Read-only verification:** objects exist; old constraint gone/new one present; `indisvalid`; trigger count; rows that
   should not change did not change; application logs without `does not exist`; route probes.
8. **Deploy** the code, then the "after deploy" migrations/backfills, then release the lock.

Credentials come from the production env file without being printed; dotenv-style quoted values must have their quotes
stripped before psql uses them (otherwise: `password authentication failed`).

### 4.11 Checking which migrations have run (without a history table)

```sql
BEGIN READ ONLY;
SELECT to_regclass('public.booking_page_day_registers') IS NOT NULL                      AS m110,
       EXISTS (SELECT 1 FROM information_schema.columns
               WHERE table_schema = 'public' AND table_name = 'users' AND column_name = 'timezone_auto') AS m115,
       EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'users_account_status_check') AS m116,
       (SELECT count(*) FROM pg_trigger WHERE tgname = 'redifu_capture')                 AS redifu_triggers;
-- INVALID indexes left by a failed CONCURRENTLY
SELECT c.relname FROM pg_index i JOIN pg_class c ON c.oid = i.indexrelid WHERE NOT i.indisvalid;
-- transactions that DDL/CONCURRENTLY would wait for
SELECT pid, state, now() - xact_start AS open_for, left(query, 80) AS query
FROM pg_stat_activity WHERE xact_start < now() - interval '1 minute' ORDER BY xact_start;
ROLLBACK;
```

With a `schema_migrations` table (§2) this probe becomes a single `SELECT`.

### 4.12 Migration checklist

**While writing**

- [ ] Number from the session's range; name `NNN_<what>.sql`; no edits to old migrations.
- [ ] Complete header (§4.2): code × schema matrix, deploy order, lock/rewrite, pre-check, how to run, rollback, rollback
      limit, backfill.
- [ ] Every statement idempotent; `BEGIN/COMMIT` + `SET LOCAL lock_timeout`, or no transaction for CONCURRENTLY + a
      validity check.
- [ ] Types follow the conventions (§1): ID, `timestamptz NOT NULL DEFAULT now()`, money `bigint`, enum `varchar` +
      CHECK, JSONB + `jsonb_typeof`, owner + owner index, deliberate FK/ON DELETE, stable constraint names.
- [ ] Every new query has an index; new columns are named in the repository's SELECT/INSERT.
- [ ] If data is written: a postcondition guard; a test of SQL literals vs Go constants.
- [ ] A new table with an owner column is in the account purge list or the retained-data list.
- [ ] If a cache reads the table: a `redifu_watch` migration ([04-caching.md](04-caching.md) §3.4).

**Before production**

- [ ] `make e2e-db-reset` (snapshot + all migrations) and e2e passes.
- [ ] Migration run 2× on a production dump copy; regression FAIL-set equal to master.
- [ ] Approval class is clear: additive or destructive (ask the user, give the row count).
- [ ] EXPLAIN before/after for indexes.

**While running**

- [ ] Deploy lock; read-only probe; backup `pre<NNN>`.
- [ ] `:5432`, one short psql, `ON_ERROR_STOP`, `lock_timeout`; record the duration.
- [ ] Read-only verification; application logs clean.
- [ ] Deploy → "after" migrations/backfills → contract separately (approval if destructive).
- [ ] Deploy log written; runbooks/docs updated.

## 5. Backfill

- Scripts in `backfills/<what>.sql`, **unnumbered**; DML for existing rows (DDL goes in migrations).
- **MUST be idempotent** (`NOT EXISTS`, `ON CONFLICT DO NOTHING`, `WHERE column IS NULL`) — run by hand, often twice.
- **MUST have a header:** what is enqueued/updated + the related migration; why; **who drains it** (worker + throughput,
  e.g. "batches of 100 every ±10 s"); when to run it; known limits.
- **MUST have verification queries** in a comment at the bottom (what remains + how to watch the queue drain). No DDL
  except `pg_temp`.
- **Report mode by default:**
  ```sql
  \set ON_ERROR_STOP on
  BEGIN;
  CREATE TEMP TABLE plan ON COMMIT DROP AS …;   -- plan + report
  UPDATE … FROM plan …;
  \if :{?commit}
  COMMIT;
  \else
  ROLLBACK;
  \echo 'Dry run: rolled back. Run again with -v commit=1 to write.'
  \endif
  ```
  `psql "$DSN" -f backfills/x.sql` = report; `psql "$DSN" -v commit=1 -f …` = write.
- **Outbox backfill:** `INSERT INTO <outbox> (…) SELECT … FROM <entity> WHERE NOT EXISTS (<same PENDING row>)`, then count
  what is still pending. Run it **after** the worker that knows the new type is live.
- **Backfills that bridge a deploy:** run before the deploy and again after it; the new code also creates missing rows on
  first use; SQL/Go equivalence is guarded by a test.
- **Needs application logic** → an idempotent CLI command (`app/command/backfill-…`), run with small pools
  (`POSTGRES_WRITE_MAX_OPEN_CONNS=2 POSTGRES_READ_MAX_OPEN_CONNS=2`) and `POSTGRES_TX_STATEMENT_TIMEOUT=0`.
- **Better without a backfill** when it can be designed that way (no row = default; old events recognized by their stored
  id).

Template: [`templates/docs/backfill.sql`](../templates/docs/backfill.sql).

## 6. Postgres connections and pools

### 6.1 Topology

- Every process (API, worker, command) opens a **read** pool, a **write** pool, and a separate pool for a library that
  needs its own connections (ledger) — this breaks the cycle "hold one write connection, wait for a second connection
  from the same pool".
- **Supabase through the pooler (Supavisor):**
  - the direct-connection host only has an AAAA record; the ECS VPC is pure IPv4 →
    `connect: cannot assign requested address`, API & worker crash-loop. **MUST**: the regional pooler host (A record)
    and the username `postgres.<project-ref>`, changed together, **through Terraform**, not the console.
  - **`:6543` (transaction mode) for the application**; **`:5432` (session mode) for manual work** (psql, migrations,
    `pg_dump`, CONCURRENTLY).
  - **Forbidden on the `:6543` path:** session-level `SET`, session advisory locks, `LISTEN/NOTIFY`, named `PREPARE`,
    temporary tables, `WITH HOLD` cursors (transaction mode does not clean up state between clients).

### 6.2 Env

| Variable | Code default | Production (example) | Meaning |
|---|---|---|---|
| `POSTGRES_{WRITE,READ}_{HOST,PORT,USERNAME,PASSWORD,DBNAME}` | port 5432 | pooler host, port **6543**, user `postgres.<ref>` | read & write to the same endpoint (no replica yet) |
| `POSTGRES_WRITE_MAX_OPEN_CONNS` / `POSTGRES_READ_MAX_OPEN_CONNS` | 100 / 100 | **10 / 10** | pool size including idle (MaxIdle = MaxOpen) |
| `LEDGER_DB_MAX_OPEN_CONNS` | 5 | **2** | library pool |
| `POSTGRES_BINARY_PARAMETERS` | false | **"true"** | required on `:6543` (§6.5) |
| `POSTGRES_SSLMODE` / `POSTGRES_SSLROOTCERT` | empty → `require` (`verify-full` when a CA is set) | `"require"` | a value outside lib/pq's 6 modes stops the process at start |
| `POSTGRES_TX_LOCK_TIMEOUT` / `_STATEMENT_TIMEOUT` / `_IDLE_TIMEOUT` | 5s / 30s / 60s | default | `SET LOCAL` per transaction |
| `LEDGER_CALL_TIMEOUT` | 40s | default | deadline for payment library calls from the request path |
| `HTTP_READ/WRITE/IDLE_TIMEOUT` | 30s / 30s / 120s | default | idle **must be > the ALB idle timeout (60 s)**, otherwise the ALB uses a connection that was just closed → 502 |

### 6.3 Pool settings in code

```go
// app/cmd/connection.go
db.SetMaxIdleConns(maxOpenConns)         // idle up to the pool size: close-and-reopen = a new handshake with the pooler
db.SetMaxOpenConns(maxOpenConns)         // requests wait in the process instead of opening connections the pooler rejects
db.SetConnMaxLifetime(3 * time.Minute)   // pooler node rotation
db.SetConnMaxIdleTime(time.Minute)       // idle connections give their slot back
// start: 10 attempts × 5 s (still within the ALB health check grace period), then panic
```

- Incident: `SetConnMaxLifetime(time.Duration(10))` = **10 nanoseconds** → a new handshake on every checkout. Durations
  **MUST** be written with units.
- Incident: a deploy failed because the pooler rejected connections while old & new tasks overlapped, and the process gave
  up on the first attempt → retry 10 × 5 s.
- Start log: `postgres <host>: connected (sslmode=<mode>)`. The DSN **MUST NOT** ever be logged.
- **`/health`:** take one write connection within 2 s, then return it; **503 only when the pool is exhausted and a ping
  through the read pool succeeds within 1 s** (the ALB stops sending traffic, ECS replaces the stuck task); other DB
  errors stay 200 and are only logged (a momentary DB disruption does not make ECS replace every task at once).

### 6.4 Pool size: the formula

- N = the largest number of concurrent processes = 2 × `api_max_capacity` (200% deploy) + worker (+ command task) —
  e.g. 2 × 4 + 1 = **9**. C = write + read + library per process.
- **Transaction mode:** requires **N × C ≤ M** (Max Client Connections per Supavisor pool; idle connections count). M = 200
  → C ≤ 22 → **10 + 10 + 2** (9 × 22 = 198). The (M+1)th client is rejected with `EMAXCONN`. A command task adds one
  process → small pools.
- **Session mode:** every client connection pins one server slot: N × C ≤ Pool Size (15) — **does not fit** more than one
  API task (incident October 13–18: 244× `EMAXCONNSESSION`, 500s during page-load bursts).
- **Server limit:** 2 × (Pool Size + 1) + other connections ≤ `max_connections` (60) → Pool Size stays at 15.
- Queueing in the pooler shows up as **latency**, not errors; beyond `pool_checkout_timeout` the pooler drops the client
  (`driver: bad connection`).
- The numbers **MUST** be recomputed whenever M, compute, or the autoscaling limits change; the formula and its values are
  commented in tfvars.

### 6.5 `binary_parameters` (a transaction-mode requirement)

- Without `binary_parameters=yes`, lib/pq sends a query with arguments in two round trips (`Parse/Describe/Sync`, then
  `Bind/Execute/Sync`); the pooler is free to put the second round trip on a different server connection →
  `unnamed prepared statement does not exist`, `bind message supplies N parameters…`, and **worst of all: the `Bind`
  attaches to another request's statement** (a valid session answered with 401, data swapped). Local evidence: PgBouncer
  873/900 failed, Supavisor 2,562/6,000 failed; with binary: 0.
- The price: lib/pq sends `[]byte` in binary format, and `jsonb`/`uuid` reject it. This **MUST** be fixed in the driver:
  `app/database` wraps the lib/pq connection and turns every `[]byte` argument into a `string` (`[]byte(nil)` stays NULL)
  — which also protects libraries. Consequence: **no `bytea` columns**.
- **Write exactly `"true"`** (an unrecognized value is read as `false` without an error).
- **Other programs' clients on `:6543` must also send each query in a single round trip** (lib/pq + binary, or the simple
  query protocol).
- **Manual work through `:6543` poisons the application's pool connections** (local test: a
  `set_config('search_path', '', false)` from a dump landed on a pooled server connection → 28/400 application queries
  failed). Recovery: terminate that user's pooler server connections through `:5432`:
  ```sql
  SELECT pg_terminate_backend(pid) FROM pg_stat_activity
  WHERE usename = current_user AND datname = current_database()
    AND backend_type = 'client backend' AND pid <> pg_backend_pid();
  ```
- **Proven release order:** phase 1 `POSTGRES_BINARY_PARAMETERS=true` on `:5432` only (the driver change kept separate
  from the pooler change) → phase 2 port 6543 **together** with the new pools → watch for 0 `EMAXCONN`, 0 driver errors,
  0 5xx. Rollback: port back to 5432. **MUST NOT** ever use `:6543` without binary parameters. Validation without staging:
  a local Supavisor with exactly the production env + an e2e burst test.

### 6.6 Timeouts

- Per transaction (§3.6): 5s / 30s / 60s, `SET LOCAL`; reached → 503, and a retry is allowed.
- Outbound calls: their own deadline (payment library 40 s, calendar API ≤ 15 s); a transaction never waits on a gateway.
- Fiber timeouts only cut the connection, never the running handler.
- Duration env vars use Go format (`5s`, `1m30s`); `0` disables the limit. An invalid pool size (`0`, `ten`) falls back to
  the default **and is announced on stderr** (`database/sql` reads 0 as unlimited). **(improvement)** treat all numeric
  and boolean env vars the same way: unrecognized value → default + warning, or fail to start.

### 6.7 TLS

- **MUST**: TLS to the pooler; the code default is `require` (encrypted, ≥ TLS 1.2, certificate not checked). `disable`
  only for a local Postgres without TLS.
- `verify-full`: the Supabase CA is not in the system trust store → ship the CA file in the image (it is public),
  `POSTGRES_SSLROOTCERT=<path>` → the mode switches to `verify-full` automatically.

### 6.8 Env & DSN pitfalls

- **An empty env var overrides `.env`** (`KEY = ""` in the task definition is not "not filled in yet"). Keys without a
  value are removed/commented out. The upside: `env KEY= ./<app> main` blanks one key for a second local instance.
- `.env` must exist (godotenv) → the image creates an empty `.env`. **(improvement)** the config loader does not require
  `.env` in production.
- **Unquoted key=value DSN:** an empty password produces `password= dbname=x` → libpq swallows `dbname`. Local: the
  `/var/run/postgresql` socket + a dummy password. **(improvement)** build the DSN with every value quoted, or as a URL.
- `getEnv` strips one pair of quotes (env from an IDE is passed verbatim); other tools (psql) do not.
- **MUST NOT** commit env files containing remote hosts or credentials (e.g. `.env.local`/`.env.staging`); only
  `.env.example`.

### 6.9 What to monitor

| Log pattern | Meaning |
|---|---|
| `EMAXCONN` | `EMAXCONNSESSION`: the 16th client in session mode; `EMAXCONN … limit: M`: N × C > M |
| `prepared statement`, `bind message`, `unsupported jsonb version number`, `incorrect binary data format` | protocol split/binary issue; must be 0 |
| `driver: bad connection` | the pooler dropped the client (checkout timeout) |
| `error_kind=unavailable` + lock name | lock queueing (lock_timeout) |
| `write pool exhausted` | the application pool is too small, not a dead DB |
| `connection attempt N of 10 failed` | rejection at start |
| `config: … using …` on stderr | a mistyped env value |
| `redifu: the database pool is busy, cached reads go to SQL` | the cache uses the write pool, which is currently full |

### 6.10 Incidents that shaped the rules

| Incident | Rule |
|---|---|
| nullable `updated_at` → scan error after insert | `NOT NULL DEFAULT now()` |
| sen vs rupiah units in the settlement fee | the unit in the field/column name |
| zero time `0001-01-01` | NULL for "not yet" |
| `DEFAULT USER` = CURRENT_USER | defaults always quoted |
| double booking, duplicate ledger accounts | per-owner lock + constraint |
| `ConnMaxLifetime(10)` = 10 ns | durations with units |
| IPv6-only direct host in an IPv4 VPC → crash-loop | pooler host + username with the ref, env through Terraform |
| deploy failed with `EMAXCONNSESSION` at start | connection retry 10 × 5 s |
| 244× `EMAXCONNSESSION` (500s during bursts) | pools from env, transaction mode + binary params |
| migration psql rejected with `EMAXCONNSESSION` | one short psql; the application on 6543 |
| psql through 6543 poisons `search_path` | manual work only through 5432 |
| indexer discards unknown types | workers never mark what they do not recognize; backfill after the worker is live |
| float noise in webhook amounts | parse to the nearest smallest unit, reject real decimals |

## 7. Dumps and local DBs

### 7.1 Production dumps

- **Read-only:** against production only `pg_dump` and verification `SELECT`s, through the **session pooler `:5432`**.
- **MUST**: `pg_dump` with the same major version as the server.
- `pg_dump -Fc -v -f <name>.dump`; verify with `pg_restore --list`; a manifest with the sha256 and the row count per
  table; `chmod 600`.
- Name: `<db>_prod_<YYYYMMDD>_<HHMM><zone>_<pre|post><NNN>[_<table>].dump` — the migration tag states the schema position.
- The reference dump for local testing is set in the project's AGENTS.md and updated when there is a new dump.

### 7.2 Local restore

```bash
createdb <db>_prod_post<NNN>
pg_restore --no-owner --exit-on-error -d <db>_prod_post<NNN> ~/backup/<dump>
# selected tables only (analysis without production read approval), then dropdb:
createdb <db>_x && pg_restore --no-owner -d <db>_x -t ledger_accounts -t ledger_entries <dump>
```

- **Only into a local Postgres**, into a **new** database. Testing a new migration: run it on that copy **twice**.

### 7.3 The e2e DB (harness)

`make e2e-db-reset` = `dropdb`/`createdb` → **production schema snapshot** (`pg_restore --schema-only` from a dump,
stored in `scripts/e2e/local/schema_prod_<date>_post<NNN>.sql`) → every numbered migration > `SCHEMA_LEVEL` (one psql
per file, autocommit) → `seed.sql` (reference data only: fee configuration, templates, holidays, system accounts) → flush
the e2e Redis. The snapshot is refreshed from a new dump the same way, then `SCHEMA_LEVEL` is raised. Why a production
snapshot and not baseline + migrations: a long-lived production database drifts from "baseline + migrations" (indexes
that were never created, constraints that differ) — tests must run against the shape that actually exists.

- **(improvement)** harness defaults equal production, including `POSTGRES_BINARY_PARAMETERS=true` (never something that has
  to be added through `env.extra`).
- Template: [`templates/backend/e2e-local/`](../templates/backend/e2e-local/); test details:
  [07-testing-and-e2e.md](07-testing-and-e2e.md).

### 7.4 PII and local data safety

- Dumps contain real data (PII, OAuth tokens, password hashes): **MUST NOT** commit/share them; **MUST NOT** use them to
  send real notifications, emails, or payments.
- On a dump copy: blank the integration tokens and device tokens before the server starts; do not start
  message/payment-sending workers; do not change/delete real entities that have files in production storage.
- Anonymize the copy before taking screenshots (names, usernames, emails, phone numbers, customer data, transaction
  metadata).
- The local server listens on `0.0.0.0`: run it only during tests, stop it by PID.

## 8. Summary of improvements for new projects

| Improvement | Problem it prevents |
|---|---|
| One ID type (`uuid`) and a uniform `randid` width | mixed `varchar`/`uuid` → casts disable indexes, FKs cannot be created |
| `schema_migrations` + CI replay twice + periodic drift check | last migration guessed from the schema; production drift |
| Migration files own their `BEGIN/COMMIT`, the runner does not wrap them | some files ran per statement locally but as one transaction in production |
| Central `23505`/`23P01` mapper based on constraint names | an unhandled `23505` becomes a 500 |
| `SAVEPOINT` for every retry inside a transaction | retrying a code in an aborted transaction |
| `SKIP LOCKED` claim + reaper + purge for **every** outbox | some workers are only safe with a single instance; outboxes without a purge |
| e2e harness = production env (binary params) | driver behavior differs from production |
| No env files with values in the repo; a loader without a mandatory `.env` | developer env files ended up tracked; the loader needs an empty `.env` |
| Unrecognized numeric/boolean env → warning or fail to start | `GetEnvInt`/`GetEnvBool` stay silent on a wrong value |
| Test: every owner-scoped table is listed in the account purge or the retained list | does not exist yet |
